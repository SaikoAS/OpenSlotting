# Warehouse walk / Lager-Rundgang

The **Walk / Rundgang** menu opens a preparation screen and a separate first-person view of the active workspace. **Evaluation / Auswertung** is the default and keeps geometry read-only. **Editor** can change the same saved warehouse layout through the main application's existing editor and persistence path. Both reuse current article-master assignments. Source settings, article assignments and camera poses are not saved by the walk. FOV remains the existing workspace preference. No workspace/database/layout schema, dependency, external asset or network service is added.

## Evaluation and Editor

Choose **Walk mode / Rundgang-Modus** before starting or in the paused walk menu. Changing modes pauses movement and retains the observer pose. Reusing an already open walk window focuses that session with its current mode/settings; change its mode in its menu or close it before starting a new session. Modes are transient, not stored in backups.

| Mode | Left click / E under the crosshair | Available actions |
| --- | --- | --- |
| Evaluation / Auswertung | Inspect a reachable location's current articles. | Metrics, master data and available A/B comparison; no geometry writes. |
| Editor | Bind the nearest reachable object within 6 m, then activate its direct parameter fields. | Existing Structure, Zones and Locations properties; move/rotate/name/dimensions, rack configuration, floor locations, codes and placement, add/duplicate/delete, locks and undo/redo. |

In Editor, **B** opens a dedicated **Recipes / Rezepte** menu, including in an empty warehouse. Search by name or choose a category, select a recipe card, then explicitly Add. Racks open the existing configuration wizard; other recipes insert their standard geometry through the existing validated save path. Opening or selecting a recipe alone does not modify the workspace. Outside text fields, B closes the recipe menu and resumes through mouse capture; Esc/Close returns to the paused walk. Key repeat does not reopen the menu or type into a newly focused search field. B is inactive in Evaluation.

The Editor object list stays on the left during mouse look, with names/types, lock indicators and the selected object's highlight. It is passive while movement is captured. Use **Tab → Select objects / Objekte auswählen** to pause and operate the list with the mouse or keyboard. Search filters names/types; choosing a row opens that object's properties without moving it or the observer. Search/actions are hidden during movement and the list leaves room for the minimap. Evaluation hides the list.

In mouse look, left click/E binds the object and operates its direct fields. **Edit object / Objekt bearbeiten** opens the selected object's properties from the menu or preparation screen. Opening it pauses movement, releases mouse capture and confines focus. The inspector devotes its width to properties; its old add-recipe/object sidebar is hidden. Layout findings remain available in an expandable section. The warehouse stays visible behind the dialog. The inspector and recipe wizard reuse `warehouse-editor.js` without allocating another 3D renderer; location placement retains its existing schematic editor.

New objects start with their footprint centered about three meters ahead of the observer on a 100 mm grid. Their initial access-side rotation faces the observer, snapped to 90 degrees. Position, dimensions and rotation remain editable; the existing layout findings report modeled collisions.

Accepted property edits save in the current workspace. Existing locks, reconciliation, location/code preservation, collision findings and impact/deletion confirmations remain active. **Close / pause** returns to the paused walk menu. **Return with mouse look / Zurück mit Mausblick** resumes through explicit mouse capture. Closing a pending save is blocked; abandoning an unapplied rack/connection preview asks for confirmation. No unlocked mouse-navigation mode is introduced.

The separate window sends a proposed layout and its exact delivered base through the browser session. The host accepts writes only in Editor mode and rejects concurrent work or a changed layout base. The main editor validates and saves the proposal using its existing metadata-save path, with rollback on pre-commit failure. A successful reply returns a fresh layout/article projection, and the walk rebuilds its scene without moving the observer unless the changed geometry makes that position invalid. On conflict, close the inspector and use **Update data snapshot** before editing again. This does not merge concurrent geometry edits automatically.

Inspector undo/redo covers its retained edits; accepted transactions also enter the main editor's history. Refreshing from another layout clears the inspector history, so it cannot undo another window's edits accidentally. A timed-out save is not retried automatically: its result may already be committed, so refresh before continuing. Workspace switches/end-of-session clear the inspector and its history. The source CSVs/analysis remain untouched, and backups retain geometry changes through the existing warehouse layout field.

## Navigation

- Opening Walk does not capture the mouse, enter fullscreen or allow movement. Configure movement, speed, FOV and display settings, then use **Start walk / Rundgang starten**. The preview starts on a free point near the first rack's access side. The minimap shows modeled object footprints, observer position/direction and the selected location. Click a free point to select a different start position. This is an explicit position jump, not a computed walking route.
- After starting the walk, hold **WASD** or the **arrow keys** to move. Diagonal/combined input is normalized. Choose **Walk / Gehen** or **Free flight (no collision) / Freiflug (ohne Kollision)** in Movement.
- Set speed with the slider or exact numeric field, **0.1–20.0 m/s in 0.1 m/s steps**; the adjacent output also shows km/h. Walk starts at 1.4 m/s, flight at 5 m/s. Each mode retains its own selected speed for the current workspace session. Switching workspace resets these transient settings; only FOV is persisted.
- In Walk, **Space** jumps and **hold C** crouches. The explicit window fallback also offers Jump and Crouch buttons; the latter toggles crouching without holding a key. Crouching lowers eye height to 60% (minimum 0.65 m) and halves movement speed. Releasing C or turning crouching off only stands up when there is enough room. A held jump key never starts repeated jumps, and crouching prevents jumping.
- In Free flight, WASD moves along the viewing direction, **Space** ascends and **C** descends. Physical collisions and gravity are disabled, as stated in the selector and hints. Horizontal scene bounds still apply and view height is bounded to 0.3–80 m. Position, view height and mode remain visible. Switching back to Walk finds a nearby free floor position at the configured standing height. If no such point exists, flight and the current position are retained with a visible message.
- The stationary preview supports location selection but cannot be rotated by dragging. Start opens the separate walk window; click **Resume mouse look / Weiter mit Mausblick** there. **Tab** opens its pause menu; **M** toggles it outside editing controls. **Esc** releases mouse look and pauses. Resume continues at the same pose. If pointer capture fails, the walk stays paused; Resume retries capture. Mouse look is the only supported way to look around.
- Movement also stops on canvas/window blur, tab hiding and leaving the menu. Typing into search or controls never moves the observer. Merely opening the menu does not capture the pointer or start movement.
- Standing eye height is adjustable from 1,000 to 2,200 mm in Walk. An increase is rejected if there is insufficient modeled clearance at the current position. This field is disabled during flight; it retains the walking height for returning to Walk.
- **Field of view (vertical) / Sichtfeld (vertikal)** adjusts the vertical angle from **45 to 100 degrees**, default **60 degrees**. The slider previews immediately; releasing it or changing it with the keyboard saves the value locally per workspace. **Reset field of view / Sichtfeld zurücksetzen** restores 60 degrees. Reopening and backup/restore retain the angle. A failed save restores the previously saved angle and shows a message. These presentation settings never change rack dimensions or location geometry.
- Search an exact location code (outer whitespace is ignored; leading zeros and case are retained). Search selects the location without changing the observer's position. **Stand in front of location / Vor Stellplatz stellen** offers an explicit jump to a free point on that rack's access side and looks toward the selected location. If the bounded search cannot find space on that side, the existing position is retained and a message explains the failure.
- Location labels appear nearby when they are in view and not hidden behind physical parts; clicking a label or visible location area opens its details. Labels are limited to 24 nearby candidates, checked for overlap and physical occlusion. Hide the details panel for more viewing space.
- The shared rack convention is retained: viewed from the access side, bay/location indices increase from left to right, including rotated racks and ground locations.

A gold line marks each rack front; the gold arrow points out of the rack toward its access aisle. The walk displays this in both work modes and previews, with a gold legend. These marks do not represent obstacles or selectable objects and do not change walking bounds.

## Direct editing with captured mouse look

In Editor, **left click** binds the reachable object under the crosshair. The mint highlight remains until **right click** releases it, including while looking away or opening the pause menu. While bound, the crosshair only targets this object's parameter fields; nearby objects and normal location labels cannot steal selection. E is an alternative to left click. Evaluation also accepts left click for its existing read-only article dialog.

Rack fields identify bay width, each level's **clear height**, common rack depth, and modeled ground/upper location width and horizontal position. Ordinary walls, doors and rectangular floor areas also expose their basic dimensions. Junction arms and drawn routes retain the detailed inspector. Locked fields remain read-only. Fields follow the object's rotation and preview geometry, are limited to 24 non-overlapping nearby labels, and cannot be activated beyond 6 m or through modeled physical parts. Labels covered by the object list, minimap, HUD or status panel are omitted.

Aim at a field and left click to activate it. **Wheel** adjusts dimensions by 50 mm and location width/position by 10 mm; **Shift+wheel** uses 1 mm steps. Digits replace the displayed value, Backspace/Delete correct it, and **Enter** explicitly applies it through the main editor's existing validated, undoable save path. An unchanged Enter ends field editing without a write. Ctrl/Alt/Meta wheel shortcuts are not intercepted. Camera look and WASD stay available; no form focus or pointer-lock release is required.

A valid unsaved candidate is shown in amber, retaining current location colors. The status panel shows affected location/code/article counts and the total modeled collision count before Enter. Invalid dimensions, overlaps, frame-height violations, locks and out-of-bounds locations block saving. Existing IDs/codes must remain present. A candidate that would enclose the walking observer is not applied; move clear and press Enter again. Preview geometry is provisional; walking collision checks continue against the committed scene until a successful save.

**Right click** discards an uncommitted draft and releases the object without leaving mouse look. Opening a menu, losing capture/focus or hiding the page discards the draft and pauses normally, retaining the object binding; rebuilding/refreshed data, a work-mode/workspace change or session end clears the binding. The existing menu inspector and B recipe catalog remain available for larger changes. A write already submitted with Enter cannot be canceled by right click; its confirmation can update the committed scene but cannot resurrect a released binding. Writes are serialized. Stale bases and uncertain save timeouts require an explicit snapshot refresh and are never retried automatically.

All preview/field data stays transient in the browser. No new stored schema, external service, dependency or operational-data transfer to Python is introduced.

## Separate walk window and mouse look

**Start walk / Rundgang starten** opens a separate maximized Edge app window through the local Windows launcher. It uses the window's entire client area with normal title bar/taskbar behavior, without requesting browser fullscreen. The main application stays available as a preparation screen with stationary preview, speed, mode, FOV, colors, code search and minimap starting points. Movement keys and jump/crouch stay disabled there before an explicit start. No warehouse geometry is changed.

The new window begins paused with **Resume mouse look / Weiter mit Mausblick**. A click in that window is required for pointer capture; a process launch cannot transfer user activation from the main window. Movement starts only after capture is granted, including legacy APIs reporting success through `pointerlockchange`. Denial keeps the menu open and movement paused. Resume always retries pointer capture; no drag or unlocked movement mode is offered. Pending requests are invalidated when the session ends, and late owned grants are released.

While moving, only the menu hint/button, position, crosshair, nearby labels and optional minimap remain. **Tab** opens the menu and focuses Resume. **M** toggles it outside editing controls; Tab/Shift+Tab stays within the open menu. Opening it clears held keys, pauses simulation, releases the mouse and makes the background inert. Resume retains position, direction, mode and selection without rebuilding geometry. Alt+Tab switches between the walk and main application; losing focus pauses movement.

**Close walk / Rundgang schließen** or X closes only the viewer. The main application and server remain open. Repeated Start reuses a connected viewer. Closing/reloading the main application or changing workspace ends the session and clears the viewer's scene and data. Closing the viewer discards its transient pose/speeds; another launch takes the main preparation settings again. Only FOV is persisted per workspace, through the main application's save path.

Both windows require the same Edge profile and localhost origin. The launcher does not select or copy a profile. If connection fails after 18 seconds, or native launch is blocked/unsupported, an error offers **Start here / Hier starten** explicitly inside the main page, still requiring mouse capture. Restart the local server after updating the application; old servers cannot launch the new viewer. Without WebGL or modeled objects Start is disabled.

### Browser data session

A random browser session channel delivers the layout, matching article master fields, relevant calculated metrics and A/B comparison. Exact quantities/IDs are preserved; up to twenty source references per matched article are included with their total count. Original CSV bytes, normalized order rows, unrelated articles and raw provenance payloads are excluded. The walk window loads neither workspace storage nor import/analysis workers and creates no persistent workspace copy. Editor proposals travel back through this same channel; only the main application writes IndexedDB.

**Update data snapshot / Datenstand aktualisieren** in the paused menu requests current data from the main application, retaining the pose where still valid. Main-window article/layout/comparison changes become visible after refresh or a new session. Viewer FOV changes save in the main application and update its preparation slider. A workspace identity change ends the channel instead of sending another workspace's data. A lost main-window connection clears the viewer after a heartbeat timeout; device sleep and hidden-window throttling are allowed to resume before that check expires.

Python receives only an opaque session ID through the guarded `/walk-window` route and starts the bundled PowerShell/Edge helper. The viewer URL keeps this ID in its fragment, outside HTTP paths/logs. Business data travels directly between same-origin/profile browser windows using `BroadcastChannel`, not through Python, files or URL payloads. No runtime packages, cloud requests or backup/schema changes are added. The extra scene/projection is an in-memory copy; this feature makes no rendering-speed claim.

## Interacting with locations

Aim at a visible location surface within **6 m**. The crosshair prompt shows **E · Interact / E · Interagieren** and its exact code only when reachable. Otherwise it is hidden; uncoded targets identify rack, bay, level/ground and position. Press E to open a centered, scrollable article dialog inside the walk window. Physical parts occlude the ray; an old selection never substitutes for the aimed location. Rendering and selection use the same FOV. E is ignored in text fields, while paused, and while the dialog is already open.

Opening the dialog pauses walking/flying, clears held movement inputs and releases owned mouse look. Background controls become inert and Tab/Shift+Tab stay inside the dialog. The mouse operates the article selector and **Metrics / Kennzahlen**, **Master data / Stammdaten**, and **Period comparison / Periodenvergleich** sections. Multiple currently assigned articles can be inspected separately; quantities from different articles/units are not summed. Cards reuse already calculated quantity, line, order, customer, active-day and source-file counts across all validated data. Missing metrics remain unknown and known zero remains zero. Master custom values require article-master provenance, and up to twenty retained source references can be expanded. No import-row aggregation runs during interaction or movement.

**Back to walk / Zurück zum Rundgang** closes the dialog and explicitly resumes mouse look, retaining pose, FOV, selection and movement mode. Denial leaves the menu paused with a capture retry. **Close details / Details schließen** or Esc dismisses the dialog into the paused menu. Choosing a location by label/search in the viewer opens the same dialog. Use the main application for the broader article workflow; the inline fallback retains its existing article navigation. Session/workspace changes and deletion of the inspected location clear the dialog and restore background controls.

**Esc**, loss of focus or pointer release pauses movement and exposes controls. Resume is explicit; a paused walk accepts no movement keys or canvas drags. Movement settings, FOV, search and minimap controls remain in the menu. Native mouse capture and device policies require company-browser acceptance.

## Movement and geometry

Coordinates remain millimeters in saved warehouse data and are converted to meters for this view. In Walk, a 0.28 m observer radius and a body from the current foot position to eye height plus 0.15 m are checked against the actual rotated physical parts. Small movement substeps prevent crossing thin obstacles; movement can slide along walls. Jump starts with 3.8 m/s upward velocity and gravity is 9.81 m/s² (about 0.72 m maximum rise without obstacles). Vertical substeps stop at overhead parts and land on physical supports, including thin decks, or the virtual floor. Leaving a support resumes falling; logical location areas and route/function markings never support or block the observer. Pause/focus loss stops the simulation until movement resumes. These transient camera/body calculations never change stored geometry.

The scene has a virtual level floor and an adaptive grid. Its extent is derived from modeled objects plus a four-meter border, with movement confined to that extent. Real hall dimensions, ceilings, stock and continuous stairs/ramps are not inferred. Model actual walls/openings in the editor. The minimap's rack footprint does not represent an impassable solid volume; Walk uses individual parts and Free flight intentionally passes through them.

## Location evaluation

The inspector shows code, rack/bay/level/position, use, width/depth and logical support height. Current article-master assignments use the same exact code matching as 3D analysis. Available analyzed articles show their order-line count, exact formatted quantity and active-day count, plus a link to the existing article detail/source evidence. If a period comparison has already been calculated, its A/B line counts and configured period names appear for that article. Use **Check data coverage / Datenabdeckung prüfen** to inspect the coverage calendar when available.

**Current assignment is not a stock measurement.** Demand is the aggregate of the currently assigned articles across all validated included data. It is not evidence of historical location visits or actual physical occupancy. Unknown article metrics remain unknown; quantities are displayed per article rather than summed across possibly different units.

Color modes affect location outlines while physical frame/beam/deck materials remain recognizable:

| Mode | Meaning |
| --- | --- |
| Assignments | Green: current article match; blue: code without a match; muted: no code. |
| Usage | Existing Unassigned, Picking and Reserve colors. |
| Demand | Logarithmically scaled order-line totals of currently assigned analyzed articles, blue to orange relative to the current maximum. Gray means unknown, including missing metric coverage for any assigned article. A known zero remains a known low value. |

No local date filter is introduced: overall demand uses the whole current validated analysis. Configure a comparison in the main comparison workflow to see A/B counts. Explicit snapshot refresh or a new session takes the current data/language/comparison; color changes rebuild the local derived view. No import-row scans run during walking.

## Rendering and fallback

`warehouse-walk-model.js` contains meter transforms, perspective math, spatial indexing, collision movement and ray selection. `warehouse-walk-renderer.js` builds typed world-space GPU buffers and uses a true perspective matrix with a configurable 45–100-degree vertical field of view (default 60), a 0.05 m near plane and an 80 m far plane. Rendering, labels and selection rays use the same angle. The existing orthographic editor/analysis renderer remains separate. Meshes upload on scene/color changes; camera frames and live FOV previews update uniforms only. Selection has its own small outline buffer. No per-frame geometry compilation or source aggregation is needed.

The two-meter spatial grid bounds local collision/ray queries; very large obstacles use a separate list instead of unbounded grid insertion. Distant objects are clipped/fogged. The minimap background is cached; only observer/selection indicators redraw during movement. Animation stops when there is no movement or pending view change.

Without WebGL2, code search, location/assignment details and the minimap remain available. GPU loss pauses movement and reports the fallback; restored contexts rebuild GPU buffers. Pointer lock and continuous native mouse/keyboard behavior still require acceptance on the intended company browser/device.

Session/launcher regressions cover minimal snapshots, exact quantities, guarded launch requests, profile/timeout failure, workspace termination, FOV persistence and scene disposal. Runtime/release allowlists include the separate viewer; the private PowerShell helper is packaged but never served.

For manual acceptance use synthetic data. Check stationary preparation, maximized app-window launch, same-profile handoff/denial, refresh/close/relaunch, Tab/M pause/resume, focus containment, viewport sizing, WASD, mouse capture/denial/retry and Esc/Alt+Tab, passage clearances, rotated racks, floor/upper locations, minimap jumps, blocked approaches, article evaluation, period comparisons, workspace switching and GPU loss. Record browser/device-specific results separately from model/adapter tests.
